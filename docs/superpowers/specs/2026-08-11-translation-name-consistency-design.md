# 翻译卡名—正文一致性审计设计

## 背景

当前 `data/translations/*.json` 同时保存每个 pitch 版本的英文卡名、中文卡名、英文正文和中文正文。卡名被手工修改后，正文中的旧译名可能没有同步，导致同一张牌在卡名和规则文本中出现两个中文名称。现有提交应用链路已经能按英文正文命中跨卡引用，但会跳过正文引用自身的条目。

## 目标

1. 提供一个只读、可重复执行的全量审计命令，找出英文正文提到牌名但中文正文没有出现当前中文牌名的候选。
2. 保持 pitch 版本独立，审计结果逐条保留批次和变体 key，不合并不同 pitch 的数值或正文。
3. 让已有的精确旧译名替换链路覆盖自引用正文。
4. 不对审计候选做批量自动翻译；候选仍需人工确认。

## 非目标

- 不修改 `data/source/english`、英文源或 spoiler 隔离边界。
- 不把 `dist` 当作编辑源。
- 不根据相似词或模糊语义自动改写中文正文。
- 不因为审计发现候选而改变条目的 `status`。

## 方案

新增 `scripts/audit-translation-name-consistency.mjs`，读取所有正式翻译批次，建立英文牌名到卡牌 ID/当前中文译名的索引，再扫描每条包含 `text_en` 和 `text_zh` 的变体。英文正文命中牌名且中文正文没有命中该目标卡的任何当前译名时，输出候选，并标记 `self-reference` 或 `cross-reference`。已知的普通英文短语命中（例如 `Pay Up` 出现在 `pay up to` 中）作为审计过滤规则排除；其余候选只报告、不自动修改。

`scripts/apply-translation-submissions.mjs` 保留现有的旧中文名精确替换条件，仅移除“目标卡 ID 等于变更卡 ID”的跳过条件。因此，同一份经过旧译名快照校验的提交，可以安全更新本卡正文中的旧名；跨卡引用行为不变。

## 验证

- 新增测试覆盖自引用替换、跨卡替换保留现状，以及审计的自引用、跨卡和 `Pay Up` 普通短语过滤。
- 对当前已确认的 `Steelblade Shunt`，手工把正文旧译名“钢刃分流”修正为“拨刀防反”，再从翻译源重新构建 `dist`。
- 运行审计命令、针对性测试、完整测试和 `npm run build`；HTTP 测试若仍受沙箱监听权限影响，单独记录为环境限制。
